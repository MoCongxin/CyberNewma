# 受控词汇（scope）：框架默认词表与扩展规则

> **何时读**：写 spec/arch 需要 scope 取值、或判断某取值是否合规、或项目要扩展词表时读

## 受控词汇（scope）：框架默认词表与扩展规则

`spec` 与 `arch` 的命名与 frontmatter 都有一个 `scope` 字段——它标注**这份工件的作用范围/归属层**。它是检索索引的键：scope 表外值会让"按范围查有哪些决策"失效（跨 plan 检索不到）。

### 默认词表（框架自带，直接用，不必等任何项目配置）

| scope | 范围 | 典型内容 |
|---|---|---|
| `product` | 产品形态与对外行为 | CLI/UI 契约、功能行为、用户可见语义 |
| `architecture` | 系统结构与模块边界 | 分层、模块划分、依赖方向、数据流、进程/线程模型 |
| `data` | 数据模型与持久化 | schema、迁移、索引、序列化格式、一致性策略 |
| `interface` | 对外接口与协议 | API、协议、消息格式、版本兼容策略 |
| `middleware` | 可复用技术中间件 | 可被多个子系统复用的库/组件 |
| `tooling` | 开发工具链 | CI/CD、构建、测试 harness、技能/流程系统本身 |
| `security` | 安全与权限 | 认证、授权、隔离、密钥、审计 |
| `observability` | 可观测性 | 日志、指标、追踪、告警 |
| `process` | 流程与协作约定 | 工作流、评审、发布流程、文档规范 |
| `cross-cutting` | 跨多层决策 | **仅用于不物化为独立模块的横切策略** |
| `meta` | 本工作流系统自身 | spec/arch/plan/memory 系统的设计与演化 |

### 扩展规则（项目有特殊领域时才用）

1. **优先复用上表**——不要因为"我的子系统叫 XXX"就新增 scope；先问它是不是能归入 `architecture`/`data`/`interface`/`tooling` 等之一。
2. **确实需要新 scope 时**，新取值必须：① 名词短语、单数、小写连字符（`release-engineering`）；② 语义**不与表内任何一项重叠**（重叠会让检索出现双归属）；③ 在项目侧词表里**登记一行**（范围 + 典型内容），格式同上表。
3. **跨 scope 决策用 `cross-cutting`**，且必须在 arch/spec 的 Context 说明跨了哪些 scope；**能物化为独立模块的归具体 scope**，不要滥用 `cross-cutting`（它是兜底而不是省事选项）。

### 词表的位置与优先级（单一真相源）

| 优先级 | 位置 | 说明 |
|---|---|---|
| 1（最高） | **项目侧词表**（项目 `AGENTS.md` 配置节 / 规范文档 / `ARCH.md` 顶部节） | 项目若显式声明了自己的词表，**以项目为准**（项目可能整体换了一套划分） |
| 2（默认） | **本节的框架默认词表** | 项目没有自己的词表时，**直接用本节**，不必阻塞、不必问用户 |
| 3（追溯） | 旧字段名 `domain:` | 含义与 `scope:` 完全相同，改名只为避免与本模型"域（Domain）"概念冲突。**既有工件沿用旧名不算错**；新写的工件用 `scope:`；发现混用写进回报，**不要自行批量改既有工件** |

**两种阻断要分清**：

- **"项目没有词表"不是阻断理由**——用默认词表继续（本节存在就是为了消灭这个伪阻断）；
- **"我想要的取值不在（项目词表 ∪ 默认词表）内"才是阻断**——停下回报，附"建议新增取值 X + 理由 + 为什么不能归入已有项"，由项目/用户决定是否登记；**不要自造、也不要改用意思相近的表内词**。

### 使用方式

```text
docs/specs/NN-<scope>-<topic>.md      # 需求工件
docs/archs/NN-<scope>-<topic>.md      # 设计工件
memory/design/<scope>.md              # 知识沉淀层按 scope 汇总
```

**specs 与 archs 各自独立自增编号**（spec↔arch 是一对多：一个 spec 可被多个 arch 消费）。两个目录下可能出现同号同名的文件（如 `specs/03-data-export.md` 与 `archs/03-data-export.md`）——**这不算冲突**，它们靠**完整路径**区分，靠 frontmatter 的 `specs:` / `archs:` 双向引用建立对应关系。
